
# 🛠️ GitLab: Мануал по работе с репозиторием

## 📁 1. Создание личного репозитория с `.gitignore` и `README.md`

1. Перейдите в GitLab: [https://gitlab.com](https://gitlab.com).
2. Нажмите **"New Project"**.
3. Укажите:

   * **Project name** — имя проекта.
   * **Visibility level** — чаще всего **Private**.
   * Отметьте:

     * ☑️ `Initialize repository with a README`
     * ☑️ `Add .gitignore` → выберите язык проекта (например, `Python`, `Node`, и т.д.)

📷 *Скриншот 1: Настройки при создании проекта*

---

## 🌿 2. Создание веток `develop` и `master`

1. После создания репозитория перейдите в **Repository → Branches**.
2. Нажмите **"New branch"**:

   * Введите `develop`, создайте из `main` (или `master`, если он уже есть).
3. Аналогично, создайте ветку `master`, если её нет.

📷 *Скриншот 2: Создание новой ветки*

---

## ⚙️ 3. Установка ветки `develop` по умолчанию

1. Перейдите в **Settings → Repository → Default Branch**.
2. Выберите `develop` и нажмите **"Save changes"**.

📷 *Скриншот 3: Установка ветки по умолчанию*

---

## 🐞 4. Создание issue на написание текущего мануала

1. Перейдите в **Issues → New Issue**.
2. Название: `Создание мануала по работе с GitLab`.
3. Описание: перечислите, что должно быть отражено.
4. Назначьте себя и сохраните.

📷 *Скриншот 4: Создание нового issue*

---

## 🌱 5. Создание ветки по issue

1. На странице issue нажмите **"Create merge request" → Create branch"**.
2. Название ветки будет вроде `manual/1-create-gitlab-manual`.
3. Ветка создается из `develop`.

📷 *Скриншот 5: Создание ветки из issue*

---

## 🔀 6. Создание merge request в `develop`

1. После пуша изменений, нажмите **"Create merge request"**.
2. Убедитесь, что:

   * Source branch: `manual/1-create-gitlab-manual`
   * Target branch: `develop`
3. Напишите описание MR (можно упомянуть: Closes #1).

📷 *Скриншот 6: Создание Merge Request*

---

## 💬 7. Комментирование и принятие Merge Request

1. Другие участники могут оставить комментарии в MR.
2. После одобрения нажмите **"Merge"**.
3. Опционально: удалите исходную ветку после слияния.

📷 *Скриншот 7: Комментарии и Merge*

---

## 🚀 8. Формирование стабильной версии в `master` с тегом

1. Перейдите в ветку `master`.
2. Нажмите **New Merge Request** → из `develop` в `master`.
3. Назовите MR: `Release v1.0.0`, добавьте changelog.
4. После слияния:

   * Перейдите в **Repository → Tags**
   * Нажмите **"New tag"**
   * Название: `v1.0.0`, исходная ветка: `master`

📷 *Скриншот 8: Создание тега*

---

## 📝 9. Работа с Wiki проекта

1. Перейдите во вкладку **Wiki**.
2. Нажмите **"Create your first page"**.
3. Используйте Markdown.
4. Можно создавать иерархию страниц, добавлять ссылки, вложения.

📷 *Скриншот 9: Интерфейс создания wiki-страницы*

---

## ✅ Заключение

Теперь у вас есть базовый процесс:

* разработка ведётся в `develop`
* стабильные релизы попадают в `master` с версионированием
* задачи ведутся через issue → ветка → merge request → тег

---

> ⚠️ *Не забудьте защитить ветки `develop` и `master` через Settings → Repository → Protected Branches.*

Если нужно, могу также подготовить .zip-архив с примерной структурой проекта или шаблон `.gitignore`.
